# ADR-002: Loren v0.1 Technology Stack

- **Status:** Accepted
- **Date:** 2026-09-03
- **Decision owners:** Loren project

## Decision

Loren v0.1 will use:

```text
C# 14 / .NET 10 LTS
ASP.NET Core host
Blazor Web App owner UI
small Loren-owned bounded agent loop
provider-neutral IBrain boundary
  ├─ Ollama adapter
  ├─ OpenAI adapter
  └─ future providers/local models
MCP C# SDK behind Loren-owned action contracts
SQLite + Entity Framework Core
xUnit
```

The provider is replaceable compute. Loren owns identity, canonical state, memory, policy, action authorization, context assembly, and audit.

## Brain boundary

Provider SDK/API types must not cross into `Loren.Core`.

Conceptual contract:

```csharp
public interface IBrain
{
    Task<BrainTurnResult> ThinkAsync(
        BrainContext context,
        IReadOnlyList<ActionDefinition> availableActions,
        CancellationToken cancellationToken);
}
```

A brain may interpret intent, reason over prepared context, request actions, consume structured action results, and return final output.

A brain may not:

- authorize its own actions;
- directly execute privileged tools outside Loren's gateway;
- receive privileged tool credentials as ordinary context;
- own Loren's durable identity or canonical memory.

## Agent runtime

Use a small Loren-owned bounded loop rather than a broad orchestration framework for v0.1:

```text
prepare BrainContext
    -> IBrain
    -> final output OR ActionRequest
    -> Loren ActionGateway
    -> policy / approval
    -> controlled executor
    -> ActionResult
    -> IBrain
    -> bounded repeat
```

Hard turn/tool/cancellation limits belong to Loren and must be testable with fake providers.

## MCP

- use the official MCP C# SDK behind an adapter;
- normalize MCP metadata/results into Loren-owned action contracts;
- MCP is transport/integration, not Loren's canonical permission or skill model;
- provider-managed MCP execution must never create a privileged path around the Action Gateway.

## Persistence

- SQLite is the canonical v0.1 store;
- EF Core owns migrations/data access;
- provider conversation/session IDs are never durable Loren identity;
- export/restore must remain independent of provider sessions.

## Why Gate B is provider-neutral

The first M0 provider candidate was OpenAI Responses. Its credential path and provider reachability were proven, but model execution was blocked by provider billing state:

```text
HTTP 429
insufficient_quota: credit_balance_exhausted
```

Making OpenAI billing a Loren architecture gate would contradict ADR-001. Gate B therefore requires at least one real provider to prove the complete Loren-controlled action loop and cancellation boundary.

OpenAI remains a supported optional adapter; it was not the provider used to close M0.

## OpenAI adapter status

The OpenAI adapter remains valid compile-time/provider-reachability evidence:

- official OpenAI .NET package `2.12.0` builds on .NET 10;
- structured function calls are interceptable by Loren code;
- trusted secret path reaches OpenAI Responses API;
- current configured OpenAI account/project is blocked by `credit_balance_exhausted` before model execution.

This is an operational provider/account issue, not a Loren Gate B blocker.
