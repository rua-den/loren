**Status:** Active — M4 Trusted Durable Memory  
**Parent plan:** `docs/plans/master-plan.md`

v0.1 is the first version where Loren must prove identity, memory, action authorization, credentials, audit, and external tool use can work together safely enough to become a real daily-use foundation.

---

# 1. v0.1 objective

Required flows:

```text
1. "Loren, repo wedding hiện sao rồi?"
   -> resolve project/repository
   -> read current GitHub state
   -> answer from structured tool data

2. "Nhớ rằng project này production deploy phải hỏi tao."
   -> save trusted owner-provided memory/policy
   -> restart Loren
   -> retrieve the same current rule later

3. "Tạo branch và chuẩn bị thay đổi X."
   -> brain requests action
   -> Loren validates and authorizes
   -> controlled executor resolves credential
   -> GitHub write
   -> verify resulting state
   -> audit result

4. "Tại sao mày vừa làm việc đó?"
   -> reconstruct context, action request, policy decision,
      approval, execution, verification, and outcome
```

If these four flows are not trustworthy, v0.1 is not complete.

---

# 2. v0.1 non-goals

Defer broad web research, reminders/background scheduling, Gmail/Calendar, voice, native mobile apps, Home Assistant, unrestricted shell/computer use, autonomous production deployments, multi-user architecture, multi-agent orchestration, plugin marketplace, generic framework features, and dynamic multi-provider routing as a release requirement.

      |                      \      |       /
      |                       Executor Boundary
      |                              |
      |                        Secret Resolver
      |                              |
      |                        GitHub / MCP / APIs
      |
      +--> Loren-owned canonical state
            Project / Repository
            Durable Memory + provenance

Hard invariants:

> **The brain can request an action. Only Loren can authorize and execute it.**

> **The brain can consume prepared memory. It cannot silently promote model/external content into trusted owner truth.**

## M4 Slice 4 — Forget/delete semantics [IMPLEMENTED / PR #21 FINAL GATE]

PR #21 implements explicit owner forgetting:

```text
A -> B -> C(current)
 -> ForgetAsync(C)
 -> validate current target
 -> reverse-walk same-scope linear chain
 -> delete A -> B -> C in one SQLite transaction
 -> restart
 -> no chain record exists or reaches prepared context
```

Properties:
- only current memory can be forgotten directly;
- whole correction chain is purged to avoid resurrecting old truth;
- malformed branching/scope changes fail closed;
- each delete validates its expected supersession edge;
- transaction rollback prevents partial purge;
- unrelated memories survive;
- forgetting is separate from audit retention and has no generic audit cascade;
- no schema migration is required.

Real SQLite tests prove chain purge, restart persistence of deletion, no prepared-context resurrection, unrelated-memory survival, and fail-closed stale/unknown targets.

Implementation CI #133 / run `33865419023` — **PASS** for restore, zero-warning build, tests, format, secret scan, dependency scan and web/auth smoke.

Slice 4 closes only after final documentation-synchronized exact-head CI and PR #21 merge.

## M4 Slice 5 — Poisoning / trust-boundary acceptance [NEXT]

Final adversarial acceptance must prove:
- MODEL_INFERENCE cannot silently become owner truth, correction, permission or policy;
- EXTERNAL_CONTENT cannot self-promote into trusted owner state;
- memory content and source/provenance references are data, not instructions;
- VERIFIED_TOOL remains fact/source/time scoped and cannot grant owner permission;
- OWNER_APPROVED_INFERENCE is distinguishable from the same unapproved model inference;
- owner correction wins current owner truth in scope;
- malicious excluded records do not leak into prepared brain context;
- no existing production runtime path silently promotes model/external content into durable owner memory.

## M4 exit gate

M4 is complete only when owner-explicit memory survives restart; corrections preserve history/current-truth semantics; forget/delete removes the entire claim chain from retrieval after restart; prepared context is bounded and inspectable; hostile/model/external content cannot silently become trusted owner state; and repository CI gates are green.
