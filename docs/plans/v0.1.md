# Loren v0.1 — Useful Trustworthy Assistant Plan

**Status:** Active — roadmap rebaselined 2026-09-06  
**Parent plan:** `docs/plans/master-plan.md`  
**Architecture boundary:** ADR-001  
**Accepted stack:** ADR-002  
**Canonical state/memory lifecycle:** ADR-003  
**Action/approval/credential boundary:** ADR-004

v0.1 is the first version that should feel like an actual personal secretary rather than a collection of infrastructure components.

> **The key correction is sequencing: Loren must converse, remember, retrieve current information, research, and organize before we broaden external mutation capabilities.**

---

# 1. v0.1 objective

The owner should be able to keep Loren open and use it naturally throughout the day for questions, current information, project context, memory, lightweight organization, and a very small number of explicitly approved actions.

Required interaction classes:

```text
A. ordinary conversation / reasoning
B. current information lookup
C. project/personal context recall
D. research and synthesis with sources
E. notes / decisions / tasks
F. one explicitly approved consequential action
G. explanation/audit of what Loren did
```

---

# 2. Required owner-visible flows

## Flow 1 — ordinary conversation

```text
Owner: "Giải thích cái này cho tao dễ hiểu."
Loren: answers directly from the brain when no external fact is required.
```

## Flow 2 — current information

```text
Owner: "Tìm giúp tao thông tin mới nhất về X."
Loren:
 -> recognizes model knowledge may be stale
 -> uses read-only information/search tool
 -> returns grounded answer + sources
```

## Flow 3 — personal/project context

```text
Owner: "Project Loren hiện sao rồi?"
Loren:
 -> resolves canonical project
 -> uses trusted memory
 -> reads live external state when necessary
 -> answers naturally
```

## Flow 4 — durable memory

```text
Owner: "Nhớ rằng production deploy phải hỏi tao."
 -> durable trusted memory
 -> restart
Owner: "Rule deploy của tao là gì?"
 -> correct current answer
```

## Flow 5 — research

```text
Owner: "Research 3 lựa chọn cho tao, đưa trade-off và nguồn."
 -> bounded retrieval
 -> multiple sources
 -> source-aware synthesis
 -> distinguish sourced facts from inference
```

## Flow 6 — personal organization

```text
Owner: "Ghi decision này lại."
Owner: "Tạo task review auth flow."
Owner: "Project Loren còn task nào?"
Owner: "Đánh dấu task review auth flow xong."
```

This is durable Loren-owned state. Scheduled delivery/reminders are deferred until Gate E.

## Flow 7 — approved action through conversation

```text
Owner: "Tạo branch abc cho Loren."
 -> brain proposes typed action
 -> Loren resolves canonical target
 -> owner sees exact proposed action
 -> owner explicitly approves
 -> Gate D executes
 -> post-write verification
 -> Loren explains result
```

The already-built create-branch capability is the first proof action. The owner should not need to manually operate low-level admin fields to use it.

## Flow 8 — explain what happened

```text
Owner: "Tại sao mày vừa làm việc đó?"
 -> reconstruct request
 -> context
 -> tool facts
 -> policy
 -> approval
 -> credential purpose
 -> execution
 -> verification
 -> outcome
```

# 3. v0.1 non-goals

Not required for the first useful release:

```text
voice/STT/TTS
mobile native app
Home Assistant
unrestricted shell/computer use
autonomous production deployments
multi-user architecture
multi-agent orchestration
standing write permissions
broad background autonomy
```

Calendar/Gmail may begin in v0.1 only if a read-only vertical slice is cheap and materially improves the owner checkpoint, but they are primarily v0.2 personal-secretary integrations.

# 4. Architecture target

```text
Owner conversation
      |
      v
ASP.NET Core host / owner UI
      |
      +--> canonical context builder
      |       Project / Repository / Memory / Organization
      |
      v
Loren Runtime
      |
      +--> IBrain
      |
      +--> read-only information tools
      |       web/search/current facts
      |       GitHub read
      |       later personal connectors
      |
      +--> ActionGateway for consequential actions
              policy
              approval
              credential boundary
              executor
              verification
              audit
```

Hard invariants:

> **Retrieved information is data, not authority.**

> **The brain can request actions; only Loren authorizes and executes them.**

> **Authentication is not write approval.**

> **A write is not successful until Loren verifies the intended postcondition.**

# 6. Current execution — M6A Conversational Secretary + Information

## M6A.1 — Conversation primary surface [NEXT]

Goal: remove the feeling that Loren is an admin dashboard with a chat box attached.

Deliver:

- conversation is the first/main surface after login;
- ordinary brain-only questions work naturally;
- canonical project context can be selected/inferred without asking the owner for low-level IDs;
- trusted memory is present in the normal conversation path;
- tool calls/results are visible as secondary activity, not the main UX;
- low-level bootstrap/debug controls move to a secondary settings/admin section;
- action proposal is represented as a conversation-level event/card, not raw form plumbing.

Acceptance:

```text
"Mày là Loren đúng không?"
"Giải thích repository pattern cho tao."
"Mày nhớ project Loren đang dùng stack gì?"
"Repo Loren hiện sao rồi?"
```

## M6A.2 — Read-only current-information action

Introduce a provider-neutral information/search contract.

Minimum action capabilities:

```text
search query
retrieve result/source metadata
bounded content
source timestamp when available
URL/title/provider identity
```

Requirements:

- read-only only;
- no browser/session credential in BrainContext;
- external pages framed as inert untrusted data;
- bounded source count/content;
- deterministic fake search/retrieval tests;
- optional configured live acceptance;
- tool failures produce uncertainty, not fabricated current facts.

Acceptance examples:

```text
"Tìm tài liệu mới nhất về .NET 10 trimming."
"Framework X hiện version mới nhất là gì?"
"Có update gì gần đây về Y?"
```

## M6A.3 — Source-aware research/synthesis

Deliver:

- multi-source retrieval;
- merge/deduplicate useful sources;
- factual claims tied to source metadata where practical;
- clear distinction between retrieved fact and Loren inference;
- stale/conflicting sources surfaced instead of silently averaged;
- bounded iterative tool calls.

Acceptance:

```text
"Research 3 lựa chọn database local cho Loren, ưu nhược và nguồn."
```

## M6A.4 — Notes / Decisions / Tasks

Add durable Loren-owned organization primitives:

```text
Note
Decision
Task
TaskStatus
optional ProjectId
source/provenance
created/updated/completed timestamps
```

Required conversational operations:

```text
create
list/filter
complete/reopen task
record decision
retrieve by project/context
```

No autonomous reminder trigger yet. A due date may be stored as data, but scheduled execution waits for Gate E.

## M6A.5 — Conversational approval using existing create-branch capability

Replace the test harness UX with the real intended pattern:

```text
Owner: "Tạo branch loren/info-layer từ main cho tao."
Brain: proposes github.create_branch
Loren: resolves exact repository + source SHA
UI: shows proposal
     repo
     branch
     source SHA
     risk/access class
Owner: Approve
Loren: creates one-time approval
 -> credential boundary
 -> GitHub write
 -> independent verification
 -> natural completion message
```

No new write primitive is needed for this slice.

# 7. M6A owner checkpoint

This is the next point where the owner should pull `main` and test the product.

Required manual test script:

```text
1. Login and land on conversation, not an admin form.
2. Ask a normal non-current knowledge question.
3. Ask a current-information question; Loren retrieves external information and shows sources.
4. Ask about project Loren; Loren combines canonical context + memory + live GitHub read.
5. Teach Loren a durable fact/decision; restart; ask for it again.
6. Create/list/complete a task through chat.
7. Ask to create a non-default branch in natural language.
8. Review exact approval proposal and approve.
9. Loren verifies branch state and reports completion naturally.
10. Ask "tại sao mày làm vậy?" and inspect audit explanation.
```

**Do not resume file/commit/PR implementation until this checkpoint is usable.**

# 11. v0.1 release gate

Tag `v0.1.0` only when:

- the owner primarily interacts through natural conversation;
- stable questions work through the brain;
- current questions use external read tools instead of stale guessing;
- research is source-aware;
- trusted memory survives restart/correction/forget;
- basic notes/decisions/tasks are durable and usable from conversation;
- project context combines canonical state + memory + authoritative reads;
- at least one consequential action follows conversational proposal -> explicit approval -> execute -> verify -> explain;
- write credentials never leak;
- read-only and revocation stop writes;
- recovery succeeds;
- core logic remains deterministic-testable without live provider behavior.
