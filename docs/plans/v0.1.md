# Loren v0.1 — Trustworthy Core Implementation Plan

**Status:** Active — M4 Trusted Durable Memory  
**Parent plan:** `docs/plans/master-plan.md`  
**Architecture boundary:** ADR-001  
**Accepted stack:** ADR-002

v0.1 is the first version where Loren must prove identity, memory, action authorization, credentials, audit, and external tool use can work together safely enough to become a real daily-use foundation.

---

# 1. v0.1 objective

Required flows:

```text
1. "Loren, repo wedding hiện sao rồi?"
   -> resolve project/repository
   -> read current GitHub state
   -> answer from structured tool data

2. "Nhớ rằng project này production deploy phải hỏi tao."
   -> save trusted owner-provided memory/policy
   -> restart Loren
   -> retrieve the same current rule later

3. "Tạo branch và chuẩn bị thay đổi X."
   -> brain requests action
   -> Loren validates and authorizes
   -> controlled executor resolves credential
   -> GitHub write
   -> verify resulting state
   -> audit result

4. "Tại sao mày vừa làm việc đó?"
   -> reconstruct context, action request, policy decision,
      approval, execution, verification, and outcome
```

If these four flows are not trustworthy, v0.1 is not complete.

---

# 2. v0.1 non-goals

Defer broad web research, reminders/background scheduling, Gmail/Calendar, voice, native mobile apps, Home Assistant, unrestricted shell/computer use, autonomous production deployments, multi-user architecture, multi-agent orchestration, plugin marketplace, generic framework features, and dynamic multi-provider routing as a release requirement.

# 3. Architecture target

```text
Owner / Web UI
      |
      v
ASP.NET Core Host
      |
      v
Context Builder -> Loren Runtime -> IBrain
      |                  |            |
      |                  |       provider adapter
      |                  |            |
      |                  +---- ActionRequest
      |                              |
      |                              v
      |                       Action Gateway
      |                      /      |       \
      |                 Policy  Approval   Audit
      |                      \      |       /
      |                       Executor Boundary
      |                              |
      |                        Secret Resolver
      |                              |
      |                        GitHub / MCP / APIs
      |
      +--> Loren-owned canonical state
            Project / Repository
            Durable Memory + provenance
            Permission rules
            Audit history
```

Hard invariants:

> **The brain can request an action. Only Loren can authorize and execute it.**

> **The brain can consume prepared memory. It cannot silently promote model/external content into trusted owner truth.**

## M4 Slice 4 — Forget/delete semantics [NEXT]

Implement explicit owner forgetting that removes a current durable-memory claim from future retrieval/context after restart. Correction chains must be handled deterministically. Memory forgetting must not reuse a generic audit-delete cascade; memory and audit retention remain separate concepts under ADR-003.

## M4 Slice 5 — Poisoning / trust-boundary acceptance [FOLLOW-UP]

Prove:

- MODEL_INFERENCE cannot silently become owner truth/policy;
- EXTERNAL_CONTENT cannot self-promote into trusted memory or permission;
- source references/provenance are data, not executable instructions;
- VERIFIED_TOOL cannot grant owner permission and remains time/source-scoped;
- OWNER_APPROVED_INFERENCE requires explicit approved source semantics;
- owner correction wins for current owner truth in its scope;
- prepared memory packages preserve these distinctions end to end.

## M4 exit gate

M4 is complete only when owner-explicit memory survives restart; corrections preserve history/current-truth semantics; forget/delete removes memory from retrieval after restart; prepared context is bounded and inspectable; hostile/model/external content cannot silently become trusted owner state; and repository CI gates are green.
